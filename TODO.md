# TODO — Known Issues

Global audit findings (multi-agent review, 2026-07-08). `[x]` = fixed (Opus batch 2026-07-13 + Fable architectural batch 2026-07-13). Release chores excluded.

The architectural batch passed a 23-agent adversarial review (17 findings, 15 confirmed); all confirmed defects were fixed: dirty re-pool after a cancelled body read (release now requires an actually-loaded body), `into_hyper_response` now transfers the connection guard into the escaped body (`EscapedBodyGuard`) instead of disposing mid-stream, outer retries replay ONLY idempotent methods (no error-kind heuristics), a single `RequestTimeout` no longer evicts the shared H2 client, gzip decompression fixes `Content-Encoding`/`Content-Length` headers, sub-second reuse TTL no longer truncates to 0, `as_json` restored to `-> Self` (+ new `try_as_json`), async `put_*_connection_back` wrappers restored, `shared_connections_cache()` accessor exposed for `gc()`/`clear()`, version bumped to 0.7.0.

A second review round on the fix code itself found 3 more defects, also fixed: (1) `EscapedBodyGuard` gained a `Drop` impl that returns a drained connection to the pool when the consumer stops polling at `is_end_stream()` (hyper's server for Content-Length/empty bodies) and disposes only on a genuine mid-stream drop — was previously losing reuse for the common Content-Length case; covered by 3 unit tests. (2) gzip decoding moved out of the wire-read path into `decode_gzip_if_needed`, run AFTER the connection is settled, so a decode failure no longer disposes an already-drained healthy connection. (3) `GzDecoder` → `MultiGzDecoder` so concatenated gzip members are fully decoded.

## Bad input must be an `Err`, not a panic (2026-10-02)

A url and a header value come from a service's settings as often as from code, so a typo there used to be a panic in every call. Found by the `my-no-sql-sdk` audit; then measured here on ~227k generated urls through `try_new` and ~1.8k requests (every `FlUrlMode`, with and without a path, pooled and not) against a closed loopback port, in the default, TLS and `with-ssh` builds.

- [x] **ssh part of a tunnel url** — fixed in `rust-extensions` (tag `0.1.5`, force-moved to `faaba9a`): a scheme other than `ssh`, a port that is not a `u16` and a non-ASCII name no longer panic inside `try_new`. Covered by `tests/try_new_malformed_ssh.rs`.
- [x] **url with no host** — `try_new` now returns `InvalidUrl` on both backends ([host_check.rs](src/host_check.rs)): `""`, `" "`, `http://`, `http://:8080`, `http:///path`, `http://?a=b`, `http+unix://`, and with `with-ssh` a tunnel with no ssh host (`ssh://user@:22->…`). Such a url used to be accepted and then panic in `my-http-utils`' `UrlBuilderInner::get_host_port` once a path segment was appended. This supersedes the 2026-07 note below that `try_new("")` returns `Ok`. Covered by `tests/try_new_no_host.rs`.
- [x] **host too long** — `rust-extensions`' `RemoteEndpoint::get_host_port` builds `host:port` in a `ShortString`, which panics past 255 bytes; a host of 253 bytes with no port (`:80` is appended) was enough, as was a unix socket path of 256. `try_new` now returns `InvalidUrl` for a host that does not fit together with its port (same [host_check.rs](src/host_check.rs)); everything that fits is accepted as before. Covered by `tests/try_new_long_host.rs`. The limit stays: `rust-extensions` (`23dbd4d`) documents the panic and leaves the length check to the caller that takes the address from outside.
- [x] **`https://` without a TLS provider feature** — the request returns `UnsupportedScheme` instead of `panic!`. Covered by `tests/https_without_tls.rs`.
- [x] **bytes that must not go on the wire** — `my-http-client` guards its request line and its header block with panics. `with_header` (and a model's header field) with a CR, LF or NUL in the value, or with a name that is not an HTTP token, panicked in every mode; a new line in the url's host or a space in its path panicked in `Http1NoHyper`. The header is now refused in `FlUrlHeaders::add` and the request fails with `RequestBuild`; the url bytes fail the `Http1NoHyper` request with `InvalidUrl` (the hyper modes already returned `HttpError`). Two unit tests in [fl_url_headers.rs](src/non_wasm/fl_url_headers.rs) hold the check equal to my-http-client's own rules, in both directions. Covered by `tests/forbidden_bytes.rs`.
- [x] **ssh host given as a host name** — `my-ssh` on `async-ssh2-lite` parsed the ssh host as an ip and unwrapped the result, so `ssh://user@ssh.example.com:22->…` — the form the README shows — panicked on the first request; so did an ssh user name longer than 255 bytes (`SshCredentials::to_string`). Fixed in `my-ssh`: tag `0.1.2` was force-moved to `4d102b9`, which is the rewrite on `russh` (package version `0.3.0`), so `cargo update` swaps the whole ssh implementation, not a patch. fl-url needed one change for it — `connect_to_remote_host` is `open_remote_tcp_stream` there ([ssh_connector.rs](src/non_wasm/http_connectors/ssh_connector.rs)). Covered by `tests/ssh_tunnel_request.rs`, and — because the transport under the tunnel changed — by `tests/ssh_tunnel_end_to_end.rs`, which sends real requests through a real ssh server in every `FlUrlMode`. Both build only with `with-ssh`, which CI does not test. Side effect: `with-ssh` no longer links `libssh2` / `openssl`, and links `aws-lc-sys` instead (russh's default crypto backend).
- [x] **url forms that were split wrongly** — not panics, but requests that went to the wrong place; all in `my-http-utils`' `UrlBuilder` up to `35466bd`. A url with no scheme and a `://` further on: `host:8080/api?next=http://other/x` arrived at `host:8080` as `GET /x` with `Host: other`. Every spelling of the unix scheme except `http+unix://`: `unix:///tmp/x.sock` connected to a file named `unix`. `http+unix:/tmp/x.sock`, one slash, was taken as the relative `tmp/x.sock`. An IPv6 literal with no port: `get_host()` of `http://[::1]` was `[:`. Fixed in `my-http-utils` (tag `0.1.0`, force-moved to `1d3cff0`) together with `RemoteEndpoint` in `rust-extensions` (tag `0.1.5`, force-moved to `23dbd4d`); no change was needed here. Covered by `tests/url_forms.rs`.
- [ ] **Panics left on purpose** — builder misuse rather than bad input, but both depend on what the url turns out to be: `set_ssh_password` on a url that is not a tunnel (its two siblings are a no-op there) and `with_client_certificate` on a url that is not `https://`. Decide: keep, or turn into a no-op / an error from the request.

## WASM backend added (2026-07-14)

- [x] **Single crate, two backends, one API.** `flurl` now compiles for both native and `wasm32-unknown-unknown`. The native hyper/tokio impl moved verbatim into `src/non_wasm/` (paths in the older `[x]` items below now live under `src/non_wasm/…`); a new `src/wasm/` implements the same public API on the browser `fetch` API (`web-sys`). `src/lib.rs` cfg-selects the backend and aliases its `FlUrl`/`FlUrlResponse`/… to the crate root, so call sites are unchanged across targets.
- [x] **Shared, target-agnostic pieces at the crate root**: `FlUrlError` (native-only variants + a wasm `FetchError` are `cfg`-gated on one enum), `FlUrlReadingHeaderError`, `body::*` (RNG split: `rand` on native, `Math.random` on wasm), and the drop-connection scenario.
- [x] **Deps split by target in `Cargo.toml`**: hyper/tokio/my-tls/my-http-client/rand/lazy_static/etc. under `cfg(not(wasm32))`; `web-sys`/`wasm-bindgen`/`js-sys` under `cfg(wasm32)`; `flate2` switched to the pure-Rust backend so `.compress()` works on both. Both targets build with zero warnings.
- wasm no-ops kept for signature parity: `set_connections_cache`, `accept_invalid_certificate`, `do_not_reuse_connection`, `update_mode`, `accept_gzip`, `set_not_used_connection_timeout`. wasm omits (browser can't express them): client certs, ssh, unix sockets, `get_body_as_stream`, `into_hyper_response`. Working on wasm: `set_timeout` (bounds headers via `AbortController`), `set_response_body_timeout` (bounds the body read on the same signal), `with_retries` (idempotent-only), `compress`.
- [x] **Adversarial review (8-agent workflow) fixes applied:** (1) the request-timeout `AbortController` is now cleared once headers arrive and body reads are bounded by a *separate* `set_response_body_timeout` (was: the request timer aborted the lazy body read and mis-mapped it to `FetchError`); (2) wasm `get_header` is now case-insensitive, matching native (browsers lower-case header names).
- [ ] **wasm runtime testing** — `wasm-bindgen-test` is wired now: `tests/retry_wasm.rs` runs the retry loop in headless Chrome (CI job `test-wasm`), with `fetch` swapped for a scripted stand-in. A smoke test of a real `fetch` round-trip against a server is still missing.

## Fixed — architectural batch (connection pool redesign)

- [x] **Pool contract established: HTTP/1 = exclusive checkout, H2 = shared.** An HTTP/1 connection is removed from the pool for the whole request *and response body* and returns only via the guard; H2 clients multiplex and are shared per key ([http_connections_cache.rs](src/http_clients_cache/http_connections_cache.rs) `checkout_connection`). Covered by unit tests (`http1_connection_is_checked_out_exclusively`, `h2_connection_is_shared`).
- [x] **Double-checkout / duplicate-Arc bug** — checkout now removes the item (H1); newly created H1 connections are NOT pre-inserted; put-back is the only way in.
- [x] **Connection no longer returns to the pool at response-HEAD time.** `FlUrlResponse` owns a `ConnectionReturner` guard ([connection_returner.rs](src/http_clients_cache/connection_returner.rs)); the connection is returned only after the body is fully consumed (buffered reads or stream EOF). Dropping the response/stream with an unread body **disposes** the connection.
- [x] **Eviction on error and `Connection: close`** — `execute_with_retry` calls `resolver.drop_connection` on every request error (evicts shared H2 clients); `Connection: close` and drop-worthy statuses (`should_drop_connection_by_status`, the previously dead `DropConnectionScenario` logic) cause dispose instead of re-pool.
- [x] **`do_not_reuse_connection` fixed** — no longer tears the socket down mid-body (the guard keeps it alive until the body is consumed, then the creator's no-op put-back lets it dispose); the flag is now honored for `ssh://` targets too.
- [x] **`max_connections` configurable** via `FlUrlHttpConnectionsCache::new_with_max_connections`; the cap is enforced on put-back (overflow disposes). Covered by `put_back_respects_max_connections`.
- [x] **Unbounded cache growth addressed** — expired idle connections are dropped at checkout, empty keys removed; `FlUrlHttpConnectionsCache::gc(ttl)` and `clear()` added for explicit sweeps.
- [x] **Mode and TLS identity included in cache keys** ([utils.rs](src/http_clients_cache/utils.rs)): `host:port|mode` for http, plus SNI + client-cert hash for https. Mode-mixing panic and TLS-identity mixing are gone (test `different_modes_do_not_share_connections`).
- [x] **Retry gated by replay safety** — `error_is_safe_to_retry` ([fl_url.rs](src/fl_url.rs)): connect-level failures retry for any method; anything that may have reached the server retries only for idempotent methods (method captured in `CompiledHttpRequest`). Mirrors my-http-client's internal policy instead of overriding it.
- [x] **WebSocket upgrades normalized to `Err(UpgradedToWebSocket)`** in both HTTP/1 wrapper arms; the upgraded connection is disconnected and never re-pooled ([my_http_client_wrapper_inner.rs](src/my_http_client_wrapper/my_http_client_wrapper_inner.rs)).
- [x] **`reunite` panics removed** — implemented via `tokio::io::ReadHalf::unsplit` in all four connectors; a server 101 can no longer abort the process.
- [x] **True cancel-safety in body load** — `ResponseBody::convert_to_slice_if_needed` writes the materialized `Body { body: None }` state *before* awaiting the read, so a dropped future leaves a valid enum (headers readable, body reads error).
- [x] **gzip response decompression (opt-in)** — `FlUrl::accept_gzip()` sends `Accept-Encoding: gzip` and transparently decompresses buffered reads; streams pass through raw (documented on the method).

## Open — product decision (fl-url internal)

- [x] **Http1NoHyper body framing fixed** (dependency `my-http-client`, tag `0.1.2` now at `344b63d`; fl-url's lock resolves to it): `read_headers` now applies RFC 9112 §6.3 (method + status via `response_has_body` → HEAD/1xx/204/304/CONNECT carry no body) and a new `BodyReader::UntilClose` reads close-delimited bodies instead of treating them as zero-length. `do_request`'s signature is unchanged, so fl-url is unaffected. Verified: a `Http1NoHyper` `head()` returns 200 with an empty body in ~130 ms (previously hung until the request timeout).
- [ ] **Redirect handling** — still none (3xx returned raw). Deliberately deferred: correct redirects need relative-Location resolution and cross-origin header hygiene (strip `Authorization`/`Cookie`, 303→GET rules); a half-measure is a security footgun. Design note: implement at the verb layer with a `follow_redirects(max)` builder, recompiling per hop; requires `HttpRequestBody: Clone` for 307/308 replays.
- [ ] **No size cap on body buffering** — buffered reads load the whole response; consider `set_max_body_size(usize)` returning an error on overflow. (Streaming + the new `set_response_body_timeout` are the current mitigations; in Http1NoHyper the dependency buffers length-based bodies internally anyway.)
- [ ] **Unused error variants** — `HyperError`, `IoError`, `HttpsInvalidDomainName`, `InvalidHttp1HandShake`, `CanNotEstablishConnection` remain never-constructed (timeouts are mapped now). Decide map-or-delete.
- [ ] **Windows default-feature build never CI-exercised** (`ring` + `aws-lc-sys` via my-tls); CI covers only `--no-default-features` on Windows.
